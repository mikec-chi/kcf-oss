# IR-extension remediation — the 89-rule ledger

The catalogue historically carried **89 rules classified `needs-ir-extension`** (see
[`semantics/automation-triage-overrides.json`](../semantics/automation-triage-overrides.json)). That
label meant "the IR has no field to express what this rule requires, so it cannot be enforced." Over
time some of those fields **landed** (the IR 1.1 executable-contract vocabulary), so a subset of the
89 became stale — the override still said "no such field" for a field that now exists.

This remediation makes the classification **evidence-derived and fail-closed**. The authoritative,
machine-readable status is [`semantics/ir-extension-status.json`](../semantics/ir-extension-status.json)
(schema: [`schemas/ir-extension-ledger-v1.schema.json`](../schemas/ir-extension-ledger-v1.schema.json)),
regenerated by [`tools/ir_extension_ledger.py`](../tools/ir_extension_ledger.py) and enforced by
`python tools/kcf.py check`.

## A rule is only "complete" when

its semantics are representable in authoring syntax + normalized IR; the JSON Schema validates it; the
compiler preserves it; an analyzer handler enforces it; positive + negative fixtures prove it; the
catalogue reports the right enforcement level; and the gate passes. **The existence of an IR field is
not, by itself, enforcement.**

## Ledger status vocabulary

`ir-missing` · `ir-partial` · `ir-present-handler-missing` · `partially-automated` · `automated` ·
`enforced-elsewhere` · `runtime-obligation` · `external-fact` · `human-judgment` · `advisory` ·
`superseded`

Each status is **derived from evidence**, not the override prose:

- `schemaSupport` — the required field(s) exist in `$defs/action` of `model-ir-v1`.
- `parserSupport` — the authoring keyword exists in `compiler/parser.py`.
- `normalizerSupport` — the normalizer passes the field through to the IR verbatim.
- `handler` — the catalogue assigns a `semantic_analyzer` method.
- `positiveFixture` / `negativeFixture` — the rule is exercised (a rule is `automated` only when a
  handler runs and a negative fixture emits its stable diagnostic).

## Final reconciliation — all 89 accounted for, **zero `ir-missing`**

| status | count | meaning |
|---|---|---|
| `automated` | 68 | real analyzer handler + positive/negative fixtures prove enforcement |
| `runtime-obligation` | 8 | enforced at runtime, not statically checkable from the model |
| `enforced-elsewhere` | 6 | enforced by stack/migration tooling or another automated rule |
| `human-judgment` | 3 | needs a governance decision / taxonomy that is not a model field |
| `advisory` | 3 | SHOULD-level authoring guidance surfaced by the emitter/runtime |
| `ir-partial` | 1 | `action.compose.saga` — `compensation` exists; durable multi-step saga state does not |
| **total** | **89** | |

**Slice 16 (RFC-3 action-invocation contract) — now `automated`** via `check_action_invocation` + the new
`invocations` construct (authoring `invoke <target> { arg/handles/establishes/expects/bounded }`,
**grammar stack 1.14→1.15**). All 7 `action.invoke.*`: `resolved` (target resolves to exactly one action),
`input` (args cover the target's required `provides`), `output` (`expects` matches the target's `returns`),
`failure` (target's failure modes are handled), `precondition` (target's preconditions are established),
`recursion` (direct recursion must be `bounded`), `transaction` (a required target boundary is incompatible
with a non-supporting caller). Positive: `NotifyOrder invoke GetOrderById`; negatives:
`GhostInvoke`/`BadInvoke`/`RecursiveInvoke`.

**Slice 15 (consolidated small contracts) — now `automated`** via `check_misc_contracts` + additive
fields (`retry-backoff`/`retry-classification`/`totality`; scalar → no grammar bump):
`action.retry.bound` (a retrying action must declare a bounded backoff), `action.retry.classification`
(must classify retryable failures), `action.transform.totality` (a mapping transform must declare
total/partial), `kcf.relationship.participation` (participation and governance relationships must stay
distinct). Migration: `SummarizeOrder` gained `totality partial`.

**Slice 14 (RFC-2 collection-pipeline subset) — now `automated`** via `check_collection_transforms` +
additive collection fields (`project` list, `expands`, `sort`, `aggregate`; collection members are
generic so **no grammar bump**): `action.collection.projection-unique` (projected names unique),
`action.collection.field-resolution` (projected fields exist in the input schema),
`action.collection.map-cardinality` (map preserves count; flat-map must declare `expands`),
`action.collection.order-total` (a sort needs a total order), `action.collection.aggregate-type` (a
declared aggregate function must be known). Positive: `OrderReport project total/note`; negatives:
`DupProject`/`BadField`/`BadFlatMap`/`BadSort`/`BadAgg`. Still `ir-missing`: `join-type`/`join-fanout`/
`equality`/`set-compatibility` (need cross-input stage-schema typing).

**Slice 13 (typed-predicate IR) — now `automated`** via `check_predicate_typing` + the new structured
`predicate` on rules/relationships (authoring `predicate <field>;` or `predicate <left> <op> <right>;`,
**grammar stack 1.13→1.14**): `stack.type.condition-boolean` (a bare-field condition must be boolean),
`stack.type.operator` (comparison needs comparable operands, logical needs boolean, equality needs
same-type), `kcf.relationship.condition` (a relationship's structured condition must be boolean). Prose
conditions stay unchecked (they need NL parsing); the structured predicate is the checkable, opt-in form.
Positive: `OrderConstraint predicate total gt 0`; negatives: `BadOperator`/`NonBoolCond`/`UnknownOp`/`CondRel`.

**Slice 11 (RFC-3 set/bulk shape) — now `automated`** via `check_action_io_contract` + the additive
`returns`/`pagination` fields: `action.set.output-shape` (a set command must declare its result shape),
`action.set.pagination` (a large query must declare pagination/streaming/bounded), `action.set.cascade`
(a bulk cascade must be bounded by a specific selection and authorized). Scalar fields → no grammar bump.
Migration: 4 bulk commands gained `returns count`. `action.set.input-shape` stays `ir-missing` (needs a
multi-record input-schema / tagged-variant representation).

**Slice 10 (RFC-8 specialization/lineage) — now `automated`** via `check_specialization_lineage`:
`kcf.concept.kind-compatible` (a concept's new `specializes` field must resolve and preserve the parent's
primary kind — authoring `specializes <concept>;`, **grammar stack 1.12→1.13**) and
`lineage.binding.schema` (a lineage binding's source/target must resolve to a declared schema/endpoint).
`kcf.concept.version` was **reclassified `enforced-elsewhere`** (semantic-version compliance is a
cross-revision fact, enforced by the delta/migration tooling, not the single-model analyzer). Still
`ir-missing`: `kcf.concept.trait` (needs a per-kind trait-permission taxonomy) and `lineage.complete`
(needs a "derived concept" marker; SHOULD-level). Positive: `PriorityOrder specializes Order`; negatives:
`BadSpec`/`OrphanSpec`/`BadBinding`.

**Slice 9 (RFC-7 integration contracts) — now `automated`** via `check_integration` over the existing
integration section (adapters/endpoints/retryPolicies/mappings — no new construct): `integration.protocol`
(adapter must declare protocol + serialization), `integration.contract.schema` (endpoint operation must
resolve to a declared action), `integration.retry.idempotency` (a retrying integration must require
idempotency/dedup/compensation), `integration.mapping.coverage` (required fields of a *modeled* target
must be mapped/defaulted/omitted). Negatives: an `integration` block (`NoProto`/`BadEp`/`BadRetry`/
`BadMap`/`OrphanEp`) in `semantic-failures-ir.json`.

**Slice 8 (RFC-6 relationship reasoning, subset) — now `automated`** via `check_relationship_reasoning`
over the open relationship `qualifiers` (no grammar/schema change — the parser already routes arbitrary
relationship qualifiers): `kcf.relationship.canonical` (a non-canonical direction must name the `inverse`
it derives from), `kcf.relationship.inverse` (a declared inverse must resolve to a relationship with
reversed source/target roles), `kcf.relationship.transitivity` (transitive inference only for
ORDERING/DEPENDENCY/COMPOSITION/CLASSIFICATION/CAUSATION modes). Negatives:
`NonCanonicalNoInverse`/`BadInverse`/`BadTransitive` in `semantic-failures-ir.json`. **Still `ir-missing`:**
`kcf.relationship.condition` (needs the boolean-expression IR — shared with `stack.type.condition-boolean`)
and `kcf.relationship.participation` (needs a participation/governance verb taxonomy).

**Slice 7 (RFC-3 record action I/O) — now `automated`** via `check_action_io_contract` + the additive
`provides` / `patchDialect` fields (authoring `provide <field>;` / `patch-dialect <d>;`, both scalar
members needing **no grammar bump** — the RFC-4 precedent). Closes the record.* cluster + the last 2
`ir-present-handler-missing` rules: `action.record.precondition` (a destructive command must declare a
version/precondition guard), `action.record.postcondition` (a mutation that states preconditions must
state its postconditions), `action.record.key` (a single-record op must not use a non-unique/predicate
selection), `action.record.update-fields` (a declared mutation must be a real, non-identity field),
`action.record.exists-output` (`exists` is a boolean query, not record data), `action.record.create-input`
(a create's `provides` must cover required fields), `action.record.create-readonly` (must not `provide`
a generated/identity field), `action.record.patch-format` (`patch` must declare its dialect). Positive:
`PlaceOrder` + soft-delete guards in `executable-contract`/`business-application`; negatives: 8 crafted
actions in `semantic-failures-ir.json`. Small honest migration: 4 destructive deletes gained an
`expected-version` guard.

**RFC-3 rules still `ir-missing`** — `action.invoke.*` (7: action-to-action invocation needs an
invocation/call contract construct that does not exist) and `action.set.*` (bulk input/output shape,
pagination, cascade — need a bulk-shape construct). Slice 8+.

**Slice 6 (RFC-2 typed field-level lineage) — now `automated`** via `check_transform_lineage` +
the new **`fieldMappings`** action construct (schema `$defs/fieldMapping`, authoring `map <src> -> <tgt>
[via <fn>] [null <behavior>] [unit <s> -> <t>] [lossy];`, documented in the AUTHORING EBNF). This is the
**first genuine grammar extension**: `grammarStackVersion` **1.11.0 → 1.12.0** (module-lock + matrix
re-pinned). It stays **additive / backward-compatible** — the construct is optional, so a transform that
declares no mappings is unconstrained; `irVersion` stays `1.0.0` (bumping the schema `const` would break
every existing IR doc, the same reason RFC-4's optional fields kept 1.0.0). Enforcement fires **only
where mappings are declared**, and then fully: `action.transform.source-target` (endpoints resolve to
declared fields), `.type` (source/target type-compatible or a `via` function), `.loss` (wide→narrow
numeric must be `lossy`), `.null` (required target can't receive a nullable source by propagation),
`.unit` (units share a family or convert — this also gives RFC-1 `stack.value.unit-compatible` its first
reader), `.required-coverage` (every required, non-identity output field is produced), `.reversibility`
(a reversible transform is lossless + injective). Positive proof: `SummarizeOrder` in
`executable-contract.kcf`; negatives: `LossyTransform`/`UnitTransform` in `semantic-failures-ir.json`.

**RFC-2 rules still `ir-missing`** (the field-mapping construct is scoped to single-record transforms;
these need collection-pipeline lineage / temporal-version semantics): `action.transform.totality`,
`action.transform.time`, `action.transform.version`, and the 9 `action.collection.*` (join/aggregate/
projection/set-compat) — a natural Slice 6b once the pattern is proven here.

**Slice 5 (RFC-1 type system, analyzer-only subset) — now `automated`** via `check_type_system` in
`tools/semantic_analyzer.py`, resolving against the new **primitive/unit registry**
[`config/type-system.json`](../config/type-system.json) (the RFC-1 data foundation). These read fields
already in the base IR (attribute `type`/`default`/`required`/`identity`, concept
`threshold`/`target`/`tolerance`/`weight`/`probability`/`durationValue`), so the change is
**backward-compatible with no grammar/version bump** (like Slices 2–4) — only a lowercase `string`→`String`
normalization in the delta fixture. Rules: `stack.type.known` (types resolve to a primitive or declared
concept), `stack.type.nullability` (required/identity attr must not default to null),
`stack.type.assignment` (default value type-compatible with its declared type), `stack.value.finite`
(execution/threshold/weight numbers finite), `stack.time.duration` (declared durations must advance).

**RFC-1 rules still `ir-missing`** — the 5 that need a **typed expression / field-mapping IR** to have
anything to read: `stack.type.operator` (operand/result typing), `stack.type.condition-boolean`
(conditions are prose strings today), `stack.type.collection` (element/cardinality compat in mappings),
`stack.value.unit-compatible` (unit algebra across mappings — the unit *registry* is now in place),
`stack.time.window-compatible` (window/frequency compat). These are unblocked by the RFC-2 typed
field-mapping layer (Slice 6), not by more type-registry work.

**Slice 4 — downstream/guidance reclassification.** 12 rules that will *not* get a model-IR field were
moved out of `needs-ir-extension` to their honest terminal class, each with a documented enforcement
location in [`automation-triage-overrides.json`](../semantics/automation-triage-overrides.json). The
ledger maps the catalogue's `manualClass` to a terminal status (`needs-external-facts` → the ledger's
`runtime-obligation`):

- **runtime-obligation** (`needs-external-facts`): `action.transaction.external` (cross-system atomicity
  is a runtime/topology fact — the IR-checkable slice is already `action.transaction.required`),
  `action.device.safety` (interlocks/state/timeout are hardware facts), `action.event.commit-order`
  (transactional outbox), `action.event.duplicate` (consumer inbox/idempotency),
  `action.destructive.scope` (runtime dry-run/preview count).
- **enforced-elsewhere**: `stack.governance.audit` (platform audit subsystem), `stack.name.visibility`
  (`validate_stack.py`/`lint_stack.py`), `kcf.profile.prohibited` (subsumed by the automated
  `kcf.profile.pattern-prohibited`).
- **advisory**: `stack.graph.cycle-policy`, `stack.graph.dead-end` (executable-graph authoring guidance,
  surfaced by the emitter/runtime).
- **human-judgment**: `kcf.extension.point` (needs a governance registry that is not a model field),
  `kcf.profile.relationship` ("at least as strict" is a profile-authoring judgment).

**Deliberately NOT reclassified** (kept `ir-missing` — they have a genuine IR angle, so calling them
"runtime" would be dishonest count-draining): `action.event.payload` (needs an event change-contract
construct, RFC-5), `action.compose.order` (needs a composition-ordering + read/write-set construct,
RFC-5), `action.retry.bound` / `action.retry.classification` (need a retry IR field, RFC-4).

**Slice 3 (RFC-5) — now `automated`** via the `check_destructive_bulk_semantics` handler in
`tools/semantic_analyzer.py` (positive: silent on the corpus; negative: `semantic-failures-ir.json`
`DangerousBulk`/`SoftDeleteNoRetention` emit each diagnostic):
`action.record.delete-policy` (a destructive action must declare `deleteBehavior`),
`action.destructive.recovery` (must declare `reversibility`, consistent with the delete policy — a hard
delete cannot be reversible/human-recoverable; a compensatable one must name its `compensation`),
`action.destructive.retention` (a recoverable delete must declare a `retention` window),
`action.set.limit` (a bulk mutation must declare a positive `bulkLimit`),
`action.set.order` (must declare `bulkOrdering`),
`action.set.partial-failure` (must declare `bulkFailurePolicy`, consistent with atomicity). These six
were **removed** from the automation-triage overrides; the ledger still tracks them as `automated`.

The remaining 2 `ir-present-handler-missing` rules are `action.record.precondition` /
`action.record.postcondition` (IR field `preconditions`/`postconditions`). These are **RFC-3**, not
RFC-5: the guard is authorable but "the caller must *establish* the precondition" is a runtime
obligation (see [`docs/IR-ROADMAP.md`](IR-ROADMAP.md) §RFC-3). They are handled with the rest of RFC-3
in Slice 7 (with an explicit authorable-vs-runtime boundary), not here.

**Slice 2 (RFC-4) — now `automated`** via the `check_action_execution_semantics` handler in
`tools/semantic_analyzer.py`, proven by `tests/fixtures/valid/transportation-ir.json` (silent) and
`tests/fixtures/invalid/semantic-failures-ir.json` (each emits its diagnostic):
`action.concurrency.version` (optimistic concurrency must declare a non-empty `expectedVersion` token),
`action.concurrency.lost-update` (a read-modify-write command must declare a concurrency mechanism or
explicitly accept lost updates), `action.idempotency.conditional` (a conditionally-idempotent command
must declare its `idempotencyKey`), `action.transaction.required` (a declared `transactionBoundary` must
be compatible with the action's atomicity). These four were **removed** from the automation-triage
overrides (they are now enforced, not `needs-ir-extension`); the ledger still tracks them — now as
`automated` — because it iterates the frozen original 89.

The 2 remaining `ir-present-handler-missing` rules keep `needs-ir-extension` in the automation-triage
overrides (their `reason` states honestly that the field exists and only enforcement is pending); the
ledger reclassifies them to `ir-present-handler-missing`. They move to `automated` in Slice 7 (RFC-3).
This is consistent with [`docs/IR-ROADMAP.md`](IR-ROADMAP.md), which records "vocabulary landed …
enforcement pending."

## The fail-closed gate

`tools/run_conformance.py` rebuilds the ledger live, compares it to the committed artifact (so it
can't rot), validates it against its schema, and asserts: **exactly 89** source rules, unique IDs, all
IDs known to the catalogue, evidence fields present on every entry, **no stale override** (a reason
claiming a field is missing that the schema has), **no rule with IR present mislabeled `ir-missing`**,
and **no `automated` rule without a handler + positive/negative fixtures**.

1. **(done)** status ledger + stale-classification repair.
2. **(done)** RFC-4 analyzer enforcement (`concurrency.version/lost-update`, `idempotency.conditional`,
   `transaction.required`).
3. **(done)** Implementable RFC-5 (destructive recovery/retention, delete-policy, bulk
   limit/order/partial-failure, compensation/reversibility consistency).
4. **(done)** Downstream/guidance reclassification (`transaction.external`, `device.safety`,
   `event.commit-order`/`event.duplicate`, `graph.*`, `governance.audit`, `name.visibility`,
   `profile.*`, `extension.point`) → `runtime-obligation` / `enforced-elsewhere` / `advisory` /
   `human-judgment`, each with a documented enforcement location.
5. **(done)** RFC-1 type system (analyzer-only subset + primitive/unit registry foundation; the
   expression-dependent 5 rules remain `ir-missing`, unblocked by RFC-2).
6. **(done)** RFC-2 transform lineage & typed field mapping (single-record transforms; grammar stack
   1.12.0). Remaining: collection-pipeline lineage + transform totality/time/version (Slice 6b).
7. **(done)** RFC-3 record action I/O (record.* cluster). Remaining: `action.invoke.*` + `action.set.*`
   (need invocation / bulk-shape constructs) — Slice 8+.
8. **(done)** RFC-6 relationship reasoning (canonical/inverse/transitivity). Remaining: condition
   (boolean-expression IR) + participation (verb taxonomy).
9. **(done)** RFC-7 integration contracts. 10. **(done)** RFC-8 specialization/lineage subset.
   11. **(done)** RFC-3 set/bulk shape. 12. **(done)** final automation-report reconciliation — the
   report now carries an `irExtension` section (89-rule status breakdown + ledger↔catalogue contradiction
   detection), gate-asserted contradiction-free and summing to 89.

**Slices 17–18 — the last constructs + honest terminal reclassification.** Slice 17 automated the
cross-input collection rules (`join-type`/`join-fanout`/`equality`/`set-compatibility`) via additive
`join-key`/`equality-key`/`expectedCardinality` fields. Slice 18 automated `stack.type.collection`
(a collection-cardinality attribute must default to a collection) and `stack.time.window-compatible`
(a window and its slide must use compatible units, via the unit registry), then **reclassified the last 7
rules to their honest terminal class** — because they are genuinely NOT static single-model checks:
`action.event.payload` / `action.compose.order` / `action.transform.time` → `runtime-obligation` (emit-time
payload conformance, runtime read/write-set scheduling, and timezone/DST conversion are runtime facts);
`action.transform.version` → `enforced-elsewhere` (cross-revision schema migration, like `kcf.concept.version`);
`action.set.input-shape` → `enforced-elsewhere` (a bulk op's single target entity guarantees input
uniformity); `kcf.concept.trait` → `human-judgment` (needs a per-kind trait taxonomy that is not a model
field); `lineage.complete` → `advisory` (a SHOULD-level recommendation). The only non-automated,
non-reclassified rule left is `action.compose.saga` (`ir-partial`): the forward/`compensation` half exists
in the IR, but durable multi-step saga state (a persistent orchestration construct) is genuinely a runtime
concern, so it is honestly left partial rather than faked.
